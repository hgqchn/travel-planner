# 交通、城市与 AI 旅行规划升级计划

日期：2026-09-10。此文档仅为执行计划；本轮不修改应用代码、调用付费生成接口、提交 Git 或部署服务器。

## 1. 目标与默认约定

- 保持现有原生前端、Python 后端、SQLite 和 Docker 部署方式，适配现有轻量服务器。
- “当前城市”指页面选择的城市，不使用设备 GPS 定位。
- 普通用户通过项目口令并选择用户 ID 后，可以添加城市、使用 AI、导入生成内容。
- 城市改名和删除仍由管理员处理。
- 新增默认城市最初没有景点、美食或行程，用户可手工创建或用 AI 生成。
- AI 默认按当前城市工作，支持景点、美食、行程分别生成或组合生成；生成后预览、编辑、勾选并导入。
- 数据库、现有用户、已有城市、项目口令和管理员配置均保留。

## 2. 当前代码的相关问题

- `public/assets/shanghai-metro.png` 是 3840×2374 的 PNG，整图按页面宽度显示；点击仅在新标签打开同一图片，没有页内缩放和拖动。
- `public/app.js` 的高德函数默认搜索“地铁站”，交通入口并非直接打开当前城市地图。
- 城市选择器是普通下拉框，新增城市只开放给管理员。
- `MAX_CITIES=50`；每类条目的 250 条限制覆盖整个项目，无法直接满足多城市扩展。
- 已初始化的数据库不会重新执行种子导入，仅修改种子 JSON 无法升级现有服务器。
- 后端共有 16 个 HTTP 工作线程，Nginx 代理读取超时为 30 秒；AI 长请求需要独立任务处理。
- `deepseek.md` 中检测到 API Key 格式配置，尚未验证可用性；该文件目前未纳入 Git。

## 3. 交通页面

### 高清线路图与页内查看器

1. 优先采用现有线路图来源的 SVG 原图；保留作者、来源、许可和版本日期。
2. 使用本地静态图片资源，缩略预览与高清资源按需加载；SVG 作为图片加载，不执行其内部脚本。
3. 点击后打开页内大图查看器：放大、缩小、适应窗口、复位、关闭。
4. 桌面支持滚轮缩放和鼠标拖动；手机支持双指缩放、单指拖动、双击放大。
5. 明确缩放边界，支持 Escape 关闭、键盘操作和关闭后恢复焦点，避免误触造成整页滚动。
6. 第一阶段先解决现有上海线路图，建立按城市配置地图资源的结构；其他城市提供当前城市地图和可核实的官方交通入口，不使用上海图替代。

### 高德跳转

- 将“打开城市地图”和“搜索景点”拆成两个函数。
- 预置城市保存规范名称、别名、行政区划标识和经核对的高德坐标系城市中心点，按官方 URI 打开该城市中心视图。
- 自定义城市无坐标时，按完整城市名称搜索城市本身；不默认搜索地铁站或虚构坐标。
- 景点导航继续使用当前城市与景点名称；同时核对百度入口的当前城市行为。
- 验收上海、北京、成都以及一个自定义城市在桌面与手机浏览器的实际跳转。

## 4. 城市预置、搜索与普通用户新增

### 用户操作

- 将城市下拉框改为可搜索的城市选择面板，提供搜索、常用/最近访问、按省份或地区浏览。
- 预置约 80–100 个城市：覆盖省会、自治区首府、直辖市，并扩充深圳、苏州、宁波、厦门、青岛、大连、佛山、东莞、无锡、珠海、泉州、三亚、桂林、大理、丽江、张家界、黄山、洛阳、敦煌、景德镇、延吉等旅游或经济城市。
- 内置城市支持中文、别名、拼音及首字母搜索；自定义城市至少支持名称搜索。
- 普通用户可点击“添加城市”，输入名称；匹配内置城市时复用规范信息，未匹配时可保存自定义城市。
- 相同规范名称/已知别名提示使用已有城市；避免将相似但不同的城市错误合并。
- 添加成功立即切换城市，并通过共享同步让其他用户看到；管理员删除的内置城市可以由用户显式重新添加。
- 共享同步更新数据时保留城市搜索输入、焦点、地图缩放位置和 AI 草稿，避免每次重绘打断操作。

### 数据与兼容性

- 新增独立城市目录数据文件，为城市补充搜索与地图元数据。
- 实施一次性数据库迁移：按规范名称和明确别名匹配，补齐缺少的预置城市；不覆盖已有 ID、名称、排序和旅行内容。
- 用迁移版本标记控制默认城市导入，管理员删掉的城市不会在每次重启时自动恢复。
- 城市上限暂定提高到 500；条目配额改为按城市限制，并保留可配置的项目总量上限。
- 内容快照按当前城市查询，城市清单轻量返回，避免新增城市后每次同步整个项目全部内容。

## 5. DeepSeek AI

### 模型与密钥

- 按用户要求，默认模型改为 `deepseek-v4-flash-vision-exp`；该模型尚待验证当前 Key 的访问权限及结构化生成兼容性。
- 使用 `DEEPSEEK_MODEL` 配置模型，首选推理模式；不因失败而静默降级模型。
- 服务端通过 HTTPS 调用官方 API，优先保持 Python 标准库实现，不引入新的数据库或队列服务。
- 将 Key 配入服务器环境文件 `DEEPSEEK_API_KEY`；先更新 `.gitignore` / `.dockerignore` 排除 `deepseek.md` 与实际密钥文件，并收紧本地文件权限。
- 浏览器只请求本项目后端，Key 不进入前端、镜像、仓库或日志。仅发送用户本次需求和必要的当前城市上下文。

### 用户界面

- 增加“AI 旅行助手”入口，选择景点、美食、行程或组合生成。
- 输入当前城市、出行日期、天数、人数、预算、偏好、出行节奏和补充要求；生成带日期行程时要求填写开始日期。
- 提供常用模板，如“经典三日游”“亲子轻松游”“本地美食”“已有行程补充建议”。
- 展示排队、生成中、校验中、完成、失败等状态；生成结果采用与现有内容相近的卡片供用户预览编辑，不向普通用户展示原始 JSON。
- 支持勾选导入和重新生成；导入目标固定为该次任务的城市，用户切换城市不会改变已生成任务的归属。

### 固定输出与内置提示词

采用 Responses API 的 JSON Schema 结构化输出；服务端仍独立校验字段和业务规则。执行时做最小兼容验证，若官方实际行为不满足要求，使用 JSON Output 配合相同服务端校验，并明确记录差异。

统一对象结构：

```json
{
  "schema_version": 1,
  "summary": "本次建议说明",
  "attractions": [],
  "foods": [],
  "itineraries": [],
  "notices": []
}
```

各数组元素严格对应项目现有业务字段：

| 类别 | 主要字段 |
| --- | --- |
| 景点 | name, district, category, description, duration, transport |
| 美食 | name, category, description, where_to_try, tip |
| 行程 | date, start_time, title, category, location, notes |

提示词固定城市、日期范围、条目数量和字段长度；只输出 JSON，不输出 Markdown 代码块。要求使用简体中文、避免重复和不合理赶路，不伪造订票链接、营业时间、票价或预约状态；无法核实的信息写入 notices。导航链接由程序按城市与地点生成，未核实的攻略链接留空。第一版不承诺实时票务、路线时长或自动订票。

服务端绑定城市 ID、作者、版本号、时间和导入批次，不接受模型指定这些可信字段。模型生成内容始终按普通数据处理。

### 解析与导入

1. 接收模型输出，检查是否完整结束，解析 JSON，验证 schema_version、数组结构、字段类型、必填项、长度、日期、时间及数量。
2. 拒绝截断、空响应、无效 JSON、越界字段和错误城市信息；显示可理解的失败原因，不写入半成品数据。
3. 生成预览：按当前城市已有内容标记同名景点/美食、同日期时间标题的行程，允许跳过或编辑；不自动覆盖已有内容。
4. 用户勾选后提交批量导入；提交时再次验证权限、配额和重复项，以处理多人并发变化。
5. 用 SQLite 事务原子写入所选条目，保留用户署名和活动记录；通过任务/导入标识保证重复点击或重试不重复插入。
6. 导入完成刷新当前城市列表，并汇报成功、跳过数量。

### 轻量服务器运行方式

- AI 使用后台任务和短轮询接口，不让浏览器保持一个超过 Nginx 30 秒限制的请求。
- 任务状态存入 SQLite；采用有上限的后台队列，初始同时处理 1 个 AI 任务，限制排队数量、输出长度和生成条目数。
- 使用按项目总量及用户/设备组合的调用限制；由于用户 ID 可切换，不能仅靠 ID 控制配额。
- 明确处理限流、余额不足、模型不可用、超时、网络断开和应用重启；重启后将未完成任务标记为可重试，不自动重复付费生成。
- 只导入通过验证的最终内容；一次请求失败不影响普通浏览、手工编辑和协作同步。

## 7. 验收与上线

- 地图：上海图放大后站名清晰；鼠标滚轮、拖动、按钮和移动端缩放路径可用；退出不影响页面操作。
- 城市：中文/拼音搜索、普通用户新增、重复提示、切城后数据归属正确；另一浏览器能同步看到变化。
- 迁移：使用生产备份副本验证升级；原有记录保持，重复启动不重复添加，删除城市后不自动恢复。
- AI：真实少量 API 联调，确认选定模型与输出结构；覆盖空结果、截断、超时、限流、余额不足和错误字段。
- 导入：预览编辑后写入正确类别和城市；重复点击不重复添加；失败不产生部分记录；多人操作时仍正确。
- 页面：真实浏览器点击和键盘输入验证全部流程，检查前端约束与后端规则一致，避免只测接口。
- 回归：原有登录、管理员、编辑冲突和共享同步保持可用；原网站正常运行。
- 发布：数据库一致性备份 → 提交 GitHub → 构建新镜像 → 同步服务器配置与 Key → 重建 → 检查运行提交、健康状态和公网界面。
- 本次含数据库迁移，回滚需匹配旧代码与升级前数据；保留恢复步骤。
