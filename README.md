# 旅游规划

面向浏览器的多人旅行规划网页。一个部署支持多个独立旅行项目，每个项目可包含多个城市，上海作为默认展示。每次打开网站先在弹窗中新建项目或选择已有项目；项目可有密码或无密码，进入后选择或创建无需密码的用户 ID；所有人都可以新增、编辑和删除行程、景点与美食，修改会显示编辑者和时间。

## 特点

- 登录前可点击“第一次使用？查看操作说明”，进入项目后可从主页“使用帮助”打开同一份指南，包含三步上手、城市与地点、每日计划、AI、地图、协作和导出说明；支持手机滚动阅读。
- 原生 HTML、CSS、JavaScript，没有前端依赖或构建步骤。
- Python 3.9+ 标准库后端，没有 `pip install`。
- SQLite 持久化，每个项目使用独立数据库，同一部署共享景点与美食资料缓存，适合小规模同行群组。
- 有密码的项目需验证密码；无密码项目可直接进入。未进入项目时不会返回用户、内容或活动数据。
- 进入项目后可在已有用户之间无密码切换，也可创建新的唯一 ID。
- 独立行程规划页按日期和保存顺序整理每日安排，以偏好时间段和停留时长代替每个地点的具体开始时间，支持拖动、上下移动和跨时段调整。
- 页面展示当前项目所有已排行程的城市、日期与数量，可点击切换；默认城市目录和仅浏览过的城市不计入已规划城市。同一天安排多个城市时弹窗提醒，手动保存、AI 导入或重排后均会检查，行程照常保存，可直接保留安排。由于跨城市交通尚未纳入单城每日核算，同日转场也会提示可能冲突；同一次访问中关闭后不重复打扰，相关安排变化后再次提醒，也可从城市概览主动查看。
- 每张已规划城市卡片提供“编辑城市”：修改开始日期时，整座城市的行程按相同天数平移，保留日期间隔、每日设置、地点顺序、内容及地点关联，保存前可预览新日期；“从项目行程中移除城市”经二次确认后删除该城市的全部行程，保留地点、美食和城市目录，之后仍可重新规划。改期与移除均在单个事务中完成，同行者修改过该城市的行程时会拒绝旧版本并保留日期草稿，需载入最新版后重试。
- 行程与景点清单双向关联：高亮已收录景点，保存或导入行程时自动补入明确的游览景点，景点可按“已排行程／未排行程”筛选。
- 行程页支持下载 Word（`.docx`）和 Excel（`.xlsx`），可导出当前城市或当前项目全部城市，供本地离线查看。
- 每天可打开高德“地图与路线”：确认具体地点、显示编号标记、计算步行/骑行/公交地铁/驾车路线，查看真实路段和迟到提醒；支持减少绕路的顺序预览。配置与使用见 [AMAP_SETUP.md](AMAP_SETUP.md)。
- 内置 162 座常用城市，覆盖省会、自治区首府、直辖市、主要旅游和商务目的地，包含港澳台城市；支持中文、拼音、首字母和省份搜索，同行者可直接添加城市。
- 景点、美食支持按类型筛选，显示各类型数量；批量全选只选择当前筛选结果。支持多选和批量删除，只影响当前项目；新项目选择同一城市时自动带入已缓存资料。
- 景点、美食采用固定主分类，支持多个自定义标签、标签搜索及任一／全部标签筛选。美食增加菜系字段，AI 会为特色菜肴补充具体菜系；菜系也可参与标签筛选。
- 景点支持 4A、5A 级别与等级筛选，可叠加分类、标签和行程状态，批量全选仅作用于筛选结果。按城市与名称匹配本地名录，官方数据优先，安徽和江苏另有维基百科补充；页面只显示级别信息。2026-09-11重新核对全国5A名单，增补67条官方4A记录与8条取消/降级更正；详细覆盖范围见 `SCENIC_RATINGS.md`。AI 补充也支持级别字段，来源和日期保存在后台。
- 景点卡片提供高德导航，城市的轨道交通图弹窗提供当前城市地图；美食卡片可复制“城市 美食名称”搜索词。
- 城市名称旁提供“轨道交通图”入口，仅在该城市有已收录线路图或可用图源时显示；点击打开线路图弹窗，支持页内缩放、拖动、双指操作和在线检查更新；高德、百度入口定位当前所选城市。
- DeepSeek AI 可生成景点、美食和每日行程，先预览编辑，再勾选导入，自动跳过重名条目。
- 行程页支持 AI 重新规划当前城市的全部行程或指定一天，预览确认后原子替换，生成期间的协同修改会触发冲突保护。
- 每 5 秒以 ETag 轻量同步；无变化时服务端返回空的 `304` 响应。
- 每条记录带版本号；两个人同时编辑时返回 `409`，不会静默覆盖。
- 冲突时保留本地草稿，展示对方改动，并要求用户明确载入最新版或准备覆盖。
- 用户 ID 由 SQLite 唯一约束保证不重名；设备会话令牌仅存于 `HttpOnly` Cookie，数据库只保存令牌哈希。
- 所有动态文字使用 `textContent` 渲染；外链只接受 `http://` 与 `https://`。
- 项目口令为可选启动配置；公网模板还会限制请求体、并发线程、注册与写入频率、分类条目数量。

详细图源、54 个城市的下载清单、覆盖缺口及更新说明见 [METRO_MAPS.md](METRO_MAPS.md)。

景区级别的数据范围、逐省来源、匹配规则和更新方法见 [SCENIC_RATINGS.md](SCENIC_RATINGS.md)。

## 本地运行

请先确认 Python 3.9+ 的版本和实际路径：

```sh
command -v python3
python3 --version
python3 -c "import sys; print(sys.executable)"
```

设置项目口令后启动：

```sh
cd /path/to/travel-planner
TRIP_PROJECT_CODE='换成你的项目口令' TRIP_ADMIN_PASSWORD='换成你的管理员密码' python3 server.py
```

浏览器访问 <http://127.0.0.1:8000>，管理员入口为 `/admin.html`。数据库首次启动时创建为 `data/trip.db`，导入 `seed_data.json` 和 `shanghai_extra.json`（26 个上海景点、22 种美食）。普通重启不会覆盖现有数据。

当前 Mac 本地配置保存在不纳入 Git 的 `data/local.env`（仅本机用户可读写），可在项目目录重新启动：

```sh
set -a
. ./data/local.env
set +a
/Library/Developer/CommandLineTools/usr/bin/python3 -B server.py
```

该解释器路径仅适用于当前 Mac；Linux 部署请按部署文档确认路径，不要上传本地口令文件。

本次升级的独立本地预览使用 `dev/start-local.sh`，配置和验收说明见 [LOCAL_PREVIEW.md](LOCAL_PREVIEW.md)。预览数据库是 `data/preview/trip.db`。

## 导出行程

在“行程”页点击“导出行程”，选择当前城市或当前项目的全部城市，再点击“下载 Word”或“下载 Excel”。浏览器会下载文件，手机可在下载记录或设备的“文件”中查看。

Word 按日期及保存的地点顺序整理每日安排，包含偏好时段、停留时长、备选标记、城市、地点、备注和相关链接，适合阅读与打印。Excel 提供“行程明细”和“导出说明”工作表，表头冻结并启用筛选，方便继续整理。导出包含已保存的每日预算与路线摘要，过期核算会标明需要重新计算。有已保存的出行提示时，Word 会在每日安排前加入“出行提示”章节，Excel 另加同名工作表。

行程页每个城市只显示一份“出行提示”。AI 生成或重排行程时不再生成、展示或自动保存城市提示，也不会从旧导入回执恢复提示；已有已保存提示保留。

完成当前城市的每日地点、顺序、停留与路线规划后，点击 **AI 生成行程提示**，在弹窗中确认 **已规划完毕，生成提示**。服务器读取当前城市完整的已保存行程、停留、交通方式及可用的全天核算信息，独立生成提示草稿；用户可编辑后保存，也可手动添加或删除。此操作不改行程，不把过期或缺失的路线耗时当作已核实数据，不联网核实天气、票价和预约信息。

生成的草稿携带行程和提示版本：生成期间行程变化时必须重新生成，他人修改提示时不能覆盖。任务失败可重试，查询失败重查原任务，切换城市或关闭弹窗不会把迟到结果写入另一城市。Word、Excel 只导出已保存提示。

导出读取服务器在下载时已保存的行程，不受页面分类筛选影响；AI 结果需要先确认导入。没有行程时会提示先添加。文件不会自动同步网页后续修改，请重新下载。导出接口沿用项目口令权限与项目隔离，文件只含旅行内容，不包含用户身份、口令或协作动态。

文件在内存中按 Office Open XML 格式生成，不写入服务器数据目录，无需安装额外 Python 或前端依赖。

## 管理员与城市

- 管理员密码通过 `TRIP_ADMIN_PASSWORD` 设置，与项目口令独立；修改该环境变量并重启即可更换管理员密码。
- 管理员可修改项目名称和项目口令，以及添加、改名、删除用户。管理员页面不再提供城市管理。
- 项目口令可自由设置为 1–200 个字符，不要求字母、数字组合；后台留空表示不修改。公网使用仍建议设置较长且不易猜测的口令。管理员密码不限制长度或字符组合；未设置或为空时禁用管理员登录。
- `TRIP_PROJECT_CODE` 仅用于首次建库或从旧版本升级时初始化；之后以数据库中的加盐哈希为准。后台修改的口令重启后仍然有效，旧项目访问凭证立即失效。
- 用户改名或删除会使其设备身份会话失效，需要重新选 ID；删除用户不会删除旅行内容。ID 只是署名，同行者仍可自建 ID，不适用于严格身份审计。
- 旅行页面顶部可搜索、切换或手动添加城市；新建行程、景点和美食归属当前城市。已规划城市的出行日期和移除操作在旅行页面管理。
- 景点增加可编辑导航链接，留空时默认打开高德地点搜索。小红书攻略为“上海 + 名称”的搜索链接，不是已核验的具体笔记，仍可手动替换。
- 独立交通页已移除，轨道交通图归入城市入口；未收录图源的城市隐藏入口。弹窗保留高德、百度地图入口。旧交通条目保留在数据库中，不再以列表展示。
- 升级到 v3 会保留用户、行程和已有条目，将已有上海景点/美食攻略改为小红书搜索，并一次性补充新增内容；请先备份。
- 城市目录升级仅执行一次；之后手动删除的城市不会因重启重新出现。

## 项目与共享城市资料

所有用户都可在入口弹窗中新建项目或进入已有项目，项目内旅行编辑权限一致。新建时填写名称，选择无密码或设置密码。项目列表公开展示名称与是否需要密码，不展示用户、行程或密码。每次重新打开或刷新旅行页面都会展示项目选择弹窗；刚选好项目后的内部跳转不会重复询问。原“项目管理”位置改为“切换项目”，可重新选择或创建项目。

管理员入口位于顶部用户右侧，仍使用部署管理员密码，保留项目创建、名称/口令修改、删除及用户管理功能；可以明确勾选移除项目密码。管理员新增“API 密钥设置”，分别修改 DeepSeek API Key、高德 JS API Key、高德安全密钥和高德 Web 服务 API Key。字段留空不修改，勾选清除会移除该配置。后台只显示已配置状态，不回显密钥。

密钥设置保存在数据目录的 `api-settings.json`（文件权限 0600），重启时优先于对应环境变量加载，适用于所有项目；保存后新请求生效，地图网页需要刷新，已经发出的请求继续使用原配置。备份或迁移部署时需安全地一并保留此文件。首次启动可不设置 `TRIP_PROJECT_CODE`，此时默认项目无密码；已有数据库仍保留原密码。每个项目有独立用户、会话、行程和清单，最多 20 个未删除项目。
有密码的未删除项目之间口令必须唯一，无密码项目可有多个；新建或修改时会拒绝与其他项目重复的口令。历史数据如果存在重复口令，主页会提示联系管理员修改，不会随意进入其中一个项目；原有项目链接仍可使用。口令继续以加盐哈希保存，旧的口令查找接口仍保留兼容；新的入口通过公开项目列表选择项目。

每个项目右侧的“删除项目”要求输入完整项目名称确认。删除后项目从列表移除，原链接及会话无法访问内容；独立数据库归档保留，界面暂不支持恢复。其他项目和全局景点、美食缓存保留，删除前会同步待写入缓存的资料。当前项目、默认项目及最后一个项目均可删除；没有项目时管理员仍可登录并新建。项目有排队或生成中的 AI 任务时，需等待任务结束再删除。

默认目录扩展到 162 座城市，保留原有 14 城，并覆盖省会、自治区首府、直辖市、主要旅游和商务目的地及港澳台城市。按省份分组，支持中文、拼音、首字母和省份搜索。旅游与商务城市采用代表性收录，不作热度或经济排名；参考[文旅部目的地资料](https://sjfw.mct.gov.cn/site/dataservice/culture)以及[苏州](https://tjj.suzhou.gov.cn/sztjj/tjgb/202604/3dc4b574cabd4e86b36ec5d3280e927c.shtml)、[无锡统计资料](https://www.wuxi.gov.cn/doc/2026/01/30/4726717.shtml)。

启动时会为既有项目一次性补入新增目录城市，保留已有城市 ID、别名、排序、自定义城市和行程。停止旧版城市精简操作；原 14 城中管理员已删除的城市不会因此恢复，本次新增城市之后被删除也不会在重启时重新出现。项目仍有 500 城上限，达到上限时不再自动添加。旧版已归档的历史行程继续保留在归档中，不自动恢复到清单；新增城市可按既有规则读取共享景点、美食缓存。

手机端城市弹窗使用单层原生纵向滚动，可滑动查看所有省份和底部手动添加入口；打开时不自动弹出键盘，点搜索框后再输入。

自定义城市通过后端本地文件 `china_province_cities.json` 自动匹配省份，例如赤峰归入内蒙古、宿州归入安徽、安吉归入浙江；支持市名、省份前缀及明确别名。已有城市在读取时自动补充省份，不改城市 ID、名称、排序或行程。管理员添加和改名使用同一规则，“赤峰”和“赤峰市”等同一城市名称不能重复新增。无法唯一匹配的名称仍归入自定义。

该映射与 162 城默认目录独立，不会把全国城市全部加入项目。大陆数据基于 [Administrative-divisions-of-China 的 2023-06-30 统计区划快照](https://github.com/modood/Administrative-divisions-of-China/blob/dc3a1d7acd85ca1b0979543e9259604142c52e8e/dist/pca-code.json)，覆盖 31 个省级单位的地级、县级目的地；另补充香港、澳门和台湾九座城市，合计 34 个省级分组、3404 条记录。数据来源、提交版本和校验值保存在文件中，运行时不请求外部接口。后续行政区划调整需核对来源后更新此文件并重启服务；映射版本会使旧页面同步缓存自动失效。

手动添加、编辑以及 AI 导入的景点、美食都会保存到同一服务器的全局资料库。按规范城市、分类和名称去重，同名资料更新后供后续新项目使用。缓存只包含景点、美食本身的介绍与链接，不共享行程、用户身份、项目口令或活动记录。各项目得到独立副本，修改一份不会覆盖其他项目已有副本。

新项目首次选择城市、或手动添加一个城市后首次打开，会自动带入缓存。每个城市只自动带入一次：单条或批量删除不会清理缓存，也不会在刷新、重启时重新出现。景点、美食页点击“批量删除”进入多选模式，勾选后确认删除；发生版本冲突时整批不删，需要刷新核对。

每城市每分类最多 250 条，项目总量默认 50,000 条。缓存累积超出剩余容量时，页面仍可打开并提示未带入的数量，超出部分继续保存在资料库。缓存范围是同一部署的数据目录；本地预览和阿里云服务器各自独立，不跨服务器自动同步。

## 手机外部导航与美食搜索词

景点卡片仅提供“高德导航”，城市线路图弹窗保留高德城市地图和百度城市地图，不再显示额外的网页搜索按钮。高德入口使用官方 HTTPS URI，`callnative=1` 允许目标站尝试唤起 App。景点先显示搜索列表，城市线路图弹窗显示当前城市地图。手机端直接在当前标签跳转，电脑端新开标签，均为用户点击的普通链接；没有使用定时器反复唤起或强制刷新目标页。能否打开 App 取决于手机是否安装、系统设置及浏览器策略，微信等内置浏览器可能要求在系统浏览器中打开。

导航链接在显示时兼容旧版本：带 `src=travelplanner` 标记的高德搜索，以及仅含 `keyword/city/callnative` 三项参数的旧 AI 搜索，按当前景点名称和城市重建。没有额外参数的手写链接若与旧 AI 格式完全相同，也会采用此规则。手动填写的 POI、坐标、路线、带额外搜索参数的链接保留目的地；第三方导航和高德短链接保留原地址。不会为此迁移或重写已有项目、草稿和共享缓存数据。新 AI 链接带来源标记，草稿改名后显示时会使用新名称。

美食卡片仅保留“复制搜索词”按钮和可见的“城市 美食名称”文字；复制后，可自行粘贴到美团等应用中搜索。局域网 HTTP 环境也提供复制回退；浏览器不允许复制时，可长按卡片上可见的搜索词手动复制。

## AI 旅行助手

### 行程与景点关联

保存或导入行程时，后端会把行程中的游览景点与当前项目、当前城市的景点清单关联。已有景点直接复用；明确但未收录的景点自动加入，先保存可确认的名称，介绍、时长和交通可在景点编辑中用 AI 补充。自动加入不会额外调用 AI，也不会把空白资料覆盖到共享城市缓存。

行程编辑和 AI 预览中可填写“关联景点”，支持多个名称，也可点选已添加景点。留空时保守识别地点和安排名称，不从备注里的备选建议自动添加。路口、普通道路、街道、路线，以及餐饮、住宿、交通站点不自动收录；不能确认的地点保留为普通行程文字。历史街区等可通过现有景点或手动明确关联，名称匹配支持同城明确官方别名，歧义时不猜测。

行程中的关联景点会高亮，并提供可点击的景点入口。景点页显示安排日期和“已排行程／未排行程”，行程状态筛选可叠加主分类、标签，批量操作只作用于完整筛选结果。关联使用稳定 ID；景点改名保留联系，行程改日期实时更新景点安排。删除或重新规划行程不会删除清单中的景点。手动删除景点后，普通刷新或重启不会重新创建；以后再保存含该景点的行程会按规则补入。

升级会为既有行程进行一次关联与补录；达到条目容量的城市只关联已有景点，腾出空间后重新保存行程可继续补入。正常保存和 AI 导入的关联、自动新增与原修改同一事务提交，容量或版本冲突会完整回滚。

AI 会获得当前城市已收录景点的分类、标签、介绍、建议时长、已安排日期，以及已排和未排景点名单。生成行程时可利用未安排景点，并避免与保留行程重复；重排一天时释放该日的安排，其他日期仍作为参考。AI 输出的每条行程带独立景点名称列表，预览可修改，确认导入后才自动加入清单。

### 固定分类、菜系与标签

景点主分类为历史古迹、寺庙宗教、园林公园、博物展馆、古镇街区、城市观景、自然风光、动植物园、主题乐园、购物市集、演艺文娱、休闲运动、其他地点。美食主分类为特色菜肴、火锅涮煮、烧烤烤肉、面条米粉、米饭粥类、面点饼类、汤羹炖品、风味小吃、糕点甜品、饮品、其他美食。信息不足可留为未分类。分类定义和建议标签统一维护在 `place_taxonomy.json`，由服务端传给表单和 AI；编辑时只能单选，模型使用枚举 Schema，后端也会校验并兼容已知旧分类名称。

每条景点、美食可保存最多 30 个标签，每个最多 24 字，使用逗号、顿号、分号或换行分隔；自动去除空白和重复标签，支持点击建议标签添加、点击已选标签移除。标签独立于主分类，卡片显示全部已保存标签。美食的 `cuisine` 保存具体菜系，例如本帮菜、川菜；AI 批量生成和编辑表单的“AI 补充基本信息”都会生成标签，并尽可能为特色菜肴补充菜系。不确定菜系时留空，不覆盖用户已填写的菜系和标签，生成后仍需核对保存。

主分类筛选与标签筛选叠加；多个标签默认符合任一，也可切换为符合全部。标签数量按当前城市和主分类统计，菜系同时作为可筛选标签；搜索框只搜索标签选项，不改变已选条件。“清空筛选”恢复全部。切换城市、项目、页面或身份会重置筛选；同步保留已选条件，即使所选标签暂时没有匹配。批量选择、删除只作用于当前完整筛选结果，改变分类、标签或匹配方式会退出原批量选择。

升级启动时一次性归并每个项目的旧分类，结合条目名称区分“亲子”“早餐”等宽泛类别，保留相关特征为标签；原类别明确包含的本帮菜、京菜会移入菜系。无法确定的归为未分类，可在编辑中请 AI 补充。迁移前原始条目保存在各项目的 `place_taxonomy_history` 表，修改条目会提升版本及项目同步版本，仍保留并发冲突保护。历史 AI 草稿、共享资料缓存读取时也兼容旧字段；新保存的标签和菜系会进入共享缓存。上线前仍应按备份说明备份全部项目。

后端配置 `DEEPSEEK_API_KEY` 后启用，`DEEPSEEK_MODEL` 默认 `deepseek-v4-flash-vision-exp`。该模型尚未在本项目中完成真实结构化生成验证；此前的验证使用 `deepseek-v4-pro`。模型可通过配置更新，Key 只在服务端读取。修改模型配置后需重启后端服务。

AI 助手提供可编辑的模型 ID 输入框，默认填入后端当前配置的 `DEEPSEEK_MODEL`，可直接输入其他模型 ID，无需查询模型列表。模型随任务保存，生成、重试和恢复任务使用同一个模型，不影响其他用户或任务。模型不可用时展示生成错误，不自动切换模型。

新增或编辑景点、美食时，可先输入名称，再点击“AI 补充基本信息”。助手按当前城市与已填资料生成一条建议，只填入表单中的空白基本字段，保留已有内容与链接；生成过程中手动填写的内容也不会被覆盖。景点名称若能通过明确别名匹配官方名录，或在官方合并名称中被明确列为成员，会一并修正为名录全称并显示说明。这是按城市和名录结构匹配的通用规则，例如北京的“八达岭长城”、苏州的“拙政园”、成都的“都江堰”均可使用各自的官方合并名称，介绍与交通仍针对原目标。已有独立官方名称优先，无法唯一对应时保留原名。补充结果是未保存的表单草稿，检查后仍需点击原有保存按钮。关闭表单或切换编辑对象后，迟到结果不会填入其他表单。

AI 使用固定提示词和 JSON Schema，经业务字段、日期、长度及链接校验后进入草稿；用户可以编辑和勾选内容再导入。导入在一个数据库事务内完成，跳过重复项，重复提交不会重复添加。生成时会提供所选城市的已有条目名称以减少重复；不会发送项目口令、管理员密码或设备凭证。

行程页的“AI 重新规划全部行程”会重做当前项目、当前城市的全部安排。也可在原助手内选择单日重排，日期锁定为所选日期；完整重排可调整开始日期与天数。生成前保留原行程，生成后可编辑和勾选草稿；每个目标日期至少保留一项，确认替换后才应用。替换会同步关联并补入新行程中的明确景点，保留已有景点和美食，不影响其他城市或项目。日常增量调整使用每天的“确定当天行程”：选地点、比较路线、让 AI 提建议并确认应用，保留原活动 ID 和手动约束。

重新规划任务在服务端记录待替换行程的 ID 和版本，模型只收到旅行内容。确认应用时再次比对；如果范围内的安排被新增、编辑或删除，返回冲突且保持现有内容，需刷新并重新生成。删除旧行程、写入新行程、活动记录及导入回执在同一事务完成；生成失败、取消确认或重复提交不会造成半份行程或重复替换。

不限制每日生成次数、生成间隔、同一用户未完成任务数量或排队数量，旅行天数和生成条目数量也不设业务上限。旧的每日计数不会阻止新任务。任务仍由每项目后台工作线程按顺序执行；等待期间可通过“新建任务”继续提交，并从“本机任务记录”切换查看结果。任务记录按当前项目和用户分别保存在浏览器中，只保存任务标识，不保存密钥或生成内容。切换任务前会提醒尚未导入的手工编辑；原始结果仍可重新打开。任务归属生成时的用户 ID 和设备，普通切换用户不能读取别人的任务。AI 不联网核验营业时间、票价和预约规则，出行前需核实。未配置 Key 时其他功能照常使用。

## 数据与协作规则

- 页面内容是共享数据，不以浏览器本地存储作为事实来源。
- 项目口令用于控制谁能进入整个项目；浏览器通过后会保存独立的项目访问 Cookie。
- 项目口令登录和退出不限制次数；输错口令后可立即重新输入。
- ID 仅用于署名，不是账号或密码。进入项目的同行者可以选择任意已有 ID，也可以创建新 ID。
- 同一 ID 可以在多个设备使用；切换用户不会让其他设备退出。
- 普通同行者的内容编辑权限相同，也可添加城市；项目设置、城市改名删除与用户管理仅限管理员。删除操作需要二次确认，不提供页面内恢复。
- 如部署在公网，设置足够长且不可猜的 `TRIP_PROJECT_CODE`、固定 `TRIP_PUBLIC_ORIGIN` 并启用 HTTPS。
- 只运行一个后端进程。SQLite 的 WAL 模式可支持小团队并发，但不适合多机或多进程写入。

## 备份

不要在服务运行时只复制 `.db` 文件，因为最新事务可能仍在 WAL 中。使用 Python 的 SQLite 在线备份：

```sh
python3 server.py --data-dir /var/lib/shanghai-trip \
  --backup /var/backups/shanghai-trip/trip-2026-09-08-2100.db
```

备份模式不会创建缺失的源数据库，也不会覆盖同名备份；完成完整性检查后才会原子写入目标文件。

多个项目应备份整个数据库集合（默认项目、注册子项目、已删除项目的归档、全局缓存）：

```sh
python3 backup_all.py --data-dir /var/lib/shanghai-trip \
  --output /var/backups/shanghai-trip/all-2026-09-10
```

恢复集合备份时应一并恢复目录内全部数据库。它们是分别取得的 SQLite 一致性快照，不承诺所有项目在完全同一时刻。

部署到 Linux 小服务器的完整步骤见 [DEPLOY.md](DEPLOY.md)。

已有 Docker 和宝塔 Nginx 的阿里云服务器，见 [Docker 部署与更新说明](DOCKER_DEPLOY.md)。

## 每日计划与 AI 分工

行程页可选择日期并“新增一天”，默认选中已有行程的下一天，空白日期也会保存和同步。每个日期标题提供“删除这一天”，确认后在单个事务中删除当前城市当天的全部安排（含备选）、每日设置和路线核算结果，保留地点、美食清单及其他日期；版本冲突会拒绝删除，删除后重新创建同一日期也不会接受旧草稿。

每日计划按“选地点 → 确认具体入口 → 比较路线及顺序 → 分配时段 → 保存”操作。地点按时段和停留时长安排，已取消预约时刻及入场窗口选项，历史预约字段不再参与排程。旧记录保留原始时间用于迁移追溯，映射为偏好时段；包含多个地点的旧活动可预览拆分，停留时长需重新确认。

- 主要时段为 09:00–11:00、11:00–13:00、14:00–16:00、17:00–20:00，20:00–22:00 夜游默认关闭。13:00–14:00 显示休息段，16:00–17:00 显示机动段，允许留空。
- 默认午餐、晚餐各 60 分钟，午休 30 分钟；每段交通加上至少 10 分钟或交通耗时 20% 的缓冲，全天目标机动余量 60 分钟，轻松节奏建议 90 分钟。各项可修改。
- 每日设置保存起终点、节奏、休息和时段锁定；每个时段统一显示紧凑标题，支持多个地点或留空；时段内上下移动保存顺序，跨时段拖动同步调整普通地点的所属时段，锁定时段保留。地图逐段默认公交地铁，可切换步行、骑行或驾车。
- 高德负责实际交通耗时，程序负责容量和约束校验。地点、时长或路线缺失时显示未核实，不能当作零耗时；修改安排后核算失效，15 分钟前的路线核算也需刷新。候选在各时段内基于简单地理顺序生成后逐段核算，不保证全局最短路线。
- AI 有独立的选地点、比较候选、调整安排与补全停留时长四种任务，使用 `ai_planning_prompts.py` 的严格 JSON 契约。模型只能引用提供的地点和候选，不能生成高德耗时或坐标；建议先预览再应用，版本冲突会阻止覆盖同行者的新修改。原景点、美食资料助手继续可用，原 v1 草稿兼容导入。
- 普通整城行程生成输出 v2 时间段草稿，须继续确认地点、时长并核算路线。AI 调整不会自动覆盖手动保存的顺序；需要改顺序时使用路线候选或手动移动。

详细设计见 [DAILY_PLANNING_REDESIGN.md](DAILY_PLANNING_REDESIGN.md)，高德配置见 [AMAP_SETUP.md](AMAP_SETUP.md)。重启后端或重建容器后，新模块和自动兼容迁移才会生效。迁移在各项目数据库保留旧活动快照，不删除原有行程。

### 从空白行程开始

1. **AI 整体规划**：选择城市 → AI 整体生成地点、美食及行程草稿 → 核对、编辑并确认保存 → 每天确认地图位置、交通方式及路线。AI 会创建行程日期，无需先新增一天。
2. **自己按天安排**：AI 只生成地点和美食（或自行添加）→ 确认保存清单 → 新增一天 → 从时段旁添加地点，可多选 → 调整停留时长、时段内顺序 → 规划路线。空时段和空白日允许保留。
3. **后续修改**：确定当天行程用于改地点、时段和预算；AI 微调用于小幅建议；“更多 → AI 重排这一天”生成单日新草稿，人工确认替换后重新核对路线，不影响其他日期。

“新增一天”只创建一个日期；“确定当天行程”修改已存在的一天；“规划路线”进入地图核验。地点和美食是候选清单，保存清单不代表已安排进当天行程。

### 默认停留时长

新 AI 行程使用模型推荐的停留分钟数；从地点清单添加到某一天时，自动带入该地点已有的建议时长。明确的区间（如 2–3 小时）取上限 180 分钟，以保留余量；无法明确换算的描述不猜测固定值。旧行程缺少时长时，在“确定当天行程 → AI 补全停留时长”生成并应用建议，只填写空缺，不覆盖已填写的时长或改变顺序。

每个地点均可手动修改停留分钟数。只修改备注会保留原时长及来源；实际修改停留时长后标为人工设置。时长改变后需重新核算路线与全天预算。

路线页按“顶部地图 → 横向当天行程及路段耗时 → 当前路段的起终点 → 交通方式 → 规划本段路线”操作，每次只显示一段的编辑表单。点击地点选择其下一段，末站选择上一段；也可直接点击路段。交通方式保存后需主动规划；前段变化时，受影响的后续公交标记过期，等待逐段重新规划。“全天预算与顺序优化”默认折叠。

逐段规划成功后自动把路线轨迹、耗时、换乘说明和查询时间保存到当前项目数据库，关闭弹窗、刷新或重启后可恢复查看。修改相关地点、交通方式或公交前序安排后旧路线失效；重新规划前段会清除后续公交的旧结果。保存的路线用于参考，不保证查询时的交通情况持续有效；全天核算仍保留 15 分钟的新鲜度规则。升级前仅存在浏览器内存中的路线无法恢复，需要首次重新规划。

Word 导出在对应日期下加入已保存路线轨迹图和地点编号、换乘说明；Excel 增加“路线图”工作表。图片基于已保存的高德轨迹离线绘制，北向上，不含街道底图，只显示已返回的轨迹，不为未规划路段补画直线。导出不额外调用高德接口。

行程页在当前日期的安排上方直接显示已保存路线图、路段完成数量和地点编号；点击图片或“查看 / 调整路线”可继续规划。关闭路线弹窗后立即同步，切换日期、城市或项目时显示对应路线。图片接口沿用项目与用户权限，按路线版本重新验证缓存。首页 AI 入口采用高对比度蓝色卡片和“开始规划”提示，适配手机布局。

“确定当天行程”的时间预算设置参与“规划路线 → 全天预算与顺序优化 → 核算全天”的容量计算，包含用餐、午休、每段交通缓冲和目标机动余量；保存设置不会自动调整地点顺序。

### 行程信息和开放时间

“确定当天行程”管理当前日期；转为备选的项目统一显示为“备选行程”，可直接“添加到行程中”恢复原时段。卡片显示优先级、开放和关闭时间。

未填写时间时，可在单张卡片点击“AI 补充开放时间”，或在每日编辑中点击“AI 补全开放时间”。先预览，再应用；已有时间不会覆盖。AI 可以返回未知及说明，结果标为“AI 参考，待核实”，不作为硬性开放约束。人工改动时间后按人工填写的窗口核算，单独修改备注等不会丢失 AI 来源。

“行程类别”区分地点、游览、用餐、休息和交通，用于时间预算。内部 `legacy` 仅表示一条记录含多个地点，界面改称“多地点行程（需拆分）”；新行程不提供该类别，已有记录可在每日编辑中预览拆分。

锁定时段后，手动编辑的时段选项禁用，单条保存和每日批量保存均校验已保存的锁定状态；必须先保存解除锁定，再修改时段。锁定期间仍可修改名称、停留时长和备注。转为备选会退出当天路线和时间核算，保留内容与原时段，可通过“添加到行程中”恢复。

逐段路线的两端支持搜索地点或地图选点，地图点选后显示待确认标记，点击确认才保存。修改定位会同步该行程的相邻路段并清除受影响的旧路线；骑行耗时和折线由高德骑行接口提供。

行程页按天显示：顶部日期选择器可跳转任意一天，也可使用“上一天 / 下一天”。每次仅渲染所选日期，空白日和备选行程仍可查看；切换城市或项目分别保留当前会话内的日期选择，数据同步不重置选择。新增一天后自动选中新日期，手动添加行程默认使用当前选中的日期；整份行程导出仍包含全部日期。
